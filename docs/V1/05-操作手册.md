# 05 操作手册

> 版本：V1 · 核对日期：2026-08-25（§5.3 域注册数修正为 11 个；域清单已内嵌 system 消息，`get_domain_index` 引用清理）
> 适用对象：部署人员、管理员、日常运维。

## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | **24.x（后端必需）** | `better-sqlite3` 为 Node 24 ABI（NODE_MODULE_VERSION 137）；Node 12 无法加载原生模块（本机默认 node 为 v12.18.4，务必用 nvm 切到 24） |
| npm | 与 Node 24 配套 | 本机 `D:\nvm` 含 v24.11.0 |
| 操作系统 | Windows（当前环境）/ macOS | Electron 脚本对 win32/non-win32 有分支 |
| 目标 MySQL | 5.7 兼容 | 生成 SQL 与校验规则按 MySQL 5.7 约束 |
| 网络 | 可访问 DeepSeek API | `https://api.deepseek.com` |

### Node 版本切换（本机 nvm-windows）

```powershell
# 查看已安装版本
Get-ChildItem D:\nvm -Directory

# 使用 Node 24 执行（示例，不切换全局）
& 'D:\nvm\v24.11.0\node.exe' -v

# 或设置环境变量后使用 nvm
$env:NVM_HOME = 'D:\nvm'
nvm use 24.11.0
```

> ⚠️ Electron 壳的 Node 探测依赖 `NVM_HOME` / `NVM_SYMLINK` 环境变量。若未设置，打包后的应用会回退到 PATH 上的 node.exe（本机为 v12），后端将因 ABI 不匹配启动失败。建议在系统环境变量中固定：
>
> ```powershell
> [Environment]::SetEnvironmentVariable('NVM_HOME', 'D:\nvm', 'User')
> ```

## 2. 安装与启动

### 2.1 安装依赖

```powershell
# 0) 关键：先让本会话使用 Node 24（否则 npm 是 Node 12 的旧版，且后端原生模块 ABI 不匹配）
$env:PATH = 'D:\nvm\v24.11.0;' + $env:PATH
node -v   # 应输出 v24.x

# 1) 项目根依赖
npm install

# 2) 后端依赖（better-sqlite3 会针对当前 Node ABI 编译）
cd backend; npm install; cd ..

# 3) 前端依赖
cd frontend; npm install; cd ..
```

> 若本机安装过 nvm-windows，也可 `nvm use 24.11.0` 后再执行上述命令；关键是 `node -v` 必须是 24.x。

### 2.2 开发模式启动

```powershell
# 方式一：一键启动（根目录，先等后端健康再起前端）
npm run dev

# 方式二：分进程启动（便于看日志）
npm run dev:backend    # 后端 http://localhost:5002
npm run dev:frontend   # 前端 http://localhost:5173

# 方式三：Electron 桌面（需先构建前端或使用 dev 前端）
npm run electron:dev
```

访问 http://localhost:5173（Web）或桌面窗口（Electron）。

### 2.3 构建与打包

```powershell
npm run build:frontend     # Vite 构建 → frontend/dist
npm run build:backend      # 后端（占位脚本，实质无打包）
npm run electron:build     # 前端构建 + electron-builder → dist/
```

打包产物：`dist/XTSQLQueryAgent-<version>-<arch>.exe`（win 配置 `artifactName`）。

### 2.4 生产/便携模式

Electron 打包后：

1. 优先读取**应用目录下**的 `backend/`（便携模式，即把 `backend`、`skills`、`data` 目录与 exe 放一起）；
2. 不存在则回退 `app.asar.unpacked/backend`；
3. 数据目录：应用根目录 `data/app.db`；日志目录 `logs/`；Skill 目录 `skills/`。

生产环境必须设置的环境变量（对后端子进程生效，可在启动前于系统/脚本中导出）：

```powershell
$env:NODE_ENV = 'production'
$env:ALLOW_DEFAULT_ADMIN = 'false'   # 禁止自动创建默认 admin
$env:JWT_SECRET = '<强随机字符串>'    # 显式 JWT 密钥
```

## 3. 首次使用

1. 浏览器/桌面打开应用 → 使用默认账号登录：
   - 用户名：`admin`
   - 密码：`admin123`
2. **立即修改密码**（侧边栏用户卡片 → 锁形图标）；
3. 打开“配置”（仅 admin）：
   - **数据库 Tab**：填 MySQL host/port/用户/密码/库名 → “测试连接” → “保存”；
   - **LLM Tab**：Provider 固定 DeepSeek → 填 API Key → 选择模型（从 DeepSeek 拉取）→ 选择 API 模式（Chat Completions 推荐 / Responses Beta）→ 保存；
   - **Agent Tab**：可选调整最大工具轮数 / 超时 / token 警告阈值；
4. 回到聊天页，输入自然语言问题即可。

## 4. 配置面板详解

### 4.1 数据库配置

| 字段 | 说明 |
|---|---|
| Host / Port | MySQL 地址，默认 localhost:3306 |
| Username / Password | 目标库账号（建议使用**只读账号**） |
| Database | 目标库名 |

连接池参数（代码固定，`services/mysqlPool.js`）：10 连接、15s 获取超时、30s 查询超时、10 分钟空闲回收、TCP keepalive、禁多语句。

### 4.2 LLM 配置

| 字段 | 说明 |
|---|---|
| Provider | 界面固定 DeepSeek（后端代码支持 openai/minimax/ollama 静态配置，但前端不提供切换） |
| API Key | 保存时掩码显示；不修改则留空保存（保留旧 key） |
| Model | 从 DeepSeek `GET /models` 拉取；默认 `deepseek-v4-flash`（主流程）/ `deepseek-chat`（收藏流程） |
| API 模式 | `chat_completions`（推荐，默认）/ `responses_api`（Beta） |

### 4.3 Agent 配置

| key | 默认 | 范围 | 说明 |
|---|---|---|---|
| 最大工具调用轮数 | 30 | 1-100 | Agent 循环上限 |
| 超时时间(ms) | 60000 | 1000-300000 | ⚠️ 当前仅保存展示、**不生效**（LLM fetch 固定 120s），见问题清单 A18 |
| Token 警告阈值 | 30000 | 1000-300000 | 前端进度条红色阈值 |

## 5. Skill 查看器与表维护（管理员）

### 5.1 浏览与编辑

1. 侧边栏“Skill”打开抽屉；目录树展示 `skills/` 全部文件（跳过 `skill_back` 备份目录）；
2. 点击文件在 Monaco 中查看；默认锁定（只读），点击右上角锁图标解锁后可编辑；
3. 保存后自动备份到 `skills/skill_back/<时间戳>/` 并写入 `skill_logs` 审计表；
4. 修改 `SKILL.md` / `table_index.json` / `field_config` / `ddl` 后**下次对话实时生效**（无需重启）。

### 5.2 添加新表（推荐流程）

1. Skill 抽屉 → “添加”按钮；
2. 输入表名 → “从数据库获取 DDL”（执行 `SHOW CREATE TABLE`）；
3. 选择 1+ 个业务域；
4. 提交后自动完成四件事：表加入所选域文件、`table_index.json` 新增条目（描述/关联表自动提取）、生成 `ddl/{table}.sql`、生成空 `field_config/{table}.json`；
5. 之后在 Skill 抽屉中补充 field_config（字段别名/枚举/虚拟关联/业务规则）以便 LLM 精确生成 SQL。

### 5.3 业务域说明

域路由文件 `domain_router_index.json` 当前注册 11 个域：people、department、permission、campus、course_edu、course_school、product、finance、activity、crm、study_abroad。

> ⚠️ `domains/` 目录下另有 `report.json` 但**未注册到索引**，该域不会出现在 system 消息内嵌的可用业务域清单中，其表也无法通过 `get_sliced_index(report)` 路由到（可临时用 `get_table_schema` 直接取表）。修复建议见问题清单 H7。
>
> 注：业务域清单已内嵌到 system 消息（2026-08），LLM 无需再调 `get_domain_index` 工具（该工具已从 LLM 可见工具清单移除）。

## 6. 日常运维

### 6.1 日志

| 场景 | 查看位置 |
|---|---|
| 后端系统日志 | `logs/YYYY-MM-DD/_system_app.log`、`_system_error.log` |
| LLM 调用详情（含 prompt/usage/工具） | `logs/YYYY-MM-DD/{username}_llm.log` |
| 收藏标题优化 | `logs/YYYY-MM-DD/{username}_favorite_llm.log` |
| Electron 启动失败 | `logs/electron-startup-<ts>.log`（splash 上可直接打开） |
| Skill 变更审计 | SQLite `skill_logs` 表 |

日志永不清理（按日分目录），长期运行需定期归档/清理。

### 6.2 备份

- SQLite：停服后复制 `data/app.db`（WAL 模式下同时备份 `app.db-wal`、`app.db-shm` 更稳妥）；
- Skill 资产：`skills/sql-creator-skill-v2/` 全部内容（建议纳入版本库）；
- 配置文件：SQLite `configs` 表（含 db_config/llm_config/jwt_secret，敏感）。

### 6.3 常用排查命令

```powershell
# 后端是否存活
Invoke-RestMethod http://localhost:5002/api/health

# 端口占用
netstat -ano | findstr ":5002"

# 查看 LLM 最近调用
Get-Content "logs\$(Get-Date -Format yyyy-MM-dd)\admin_llm.log" -Tail 50

# 查看错误日志
Get-Content "logs\$(Get-Date -Format yyyy-MM-dd)\_system_error.log" -Tail 50
```

### 6.4 常见故障排查

| 现象 | 排查步骤 | 常见原因 |
|---|---|---|
| Electron 启动后 splash 报“找不到 Node 可执行文件” | 查看 splash 错误详情 / 启动日志 | 未安装 Node 24 或 `NVM_HOME` 未指向 `D:\nvm` |
| 后端进程秒退 / “compiled against a different Node.js version” | 确认启动后端用的 Node 版本 | 用 Node 12 运行（better-sqlite3 ABI 不匹配）；改用 Node 24 |
| 登录报 429 | 查看是否频繁尝试 | 认证限流 10 次/h/账号，等 1 小时或重启（dev 场景可临时调低 windowMs 调试） |
| 提问后长时间无输出 | 看 `admin_llm.log` 与 `_system_error.log` | DeepSeek API Key 失效 / 余额不足 / 网络不通；整体 5min 超时 |
| 流式输出卡住 | 看单次 read 30s 超时日志 | LLM 流中断 / 网络抖动，重试即可 |
| “LLM未配置” | 打开配置面板检查 LLM Tab | apiKey 未保存（保存时留空会保留旧值，若从未配置需填写） |
| 查询报“数据库未配置” | 配置面板数据库 Tab | `db_config` 缺失或 JSON 损坏（logs 中可查） |
| 查询超时 | 看是否慢 SQL 占满连接池 | 连接池 10 个，单查询 30s 上限；避免并发大查询 |
| SQL 执行被拒 | 看错误码 | 非 SELECT/WITH、含危险函数、多语句、超长等，见 API 错误码表 |
| 表查不到 | 看可用业务域清单（system 消息内嵌）→ `get_sliced_index` | 表未加入 table_index / 域未注册（如 report） |
| Skill 保存失败 | 看 `skill_logs` 与备份目录 | 权限不足 / 路径非法（isPathSafe 拒绝） |

## 7. 安全基线（上线前检查单）

- [ ] 修改默认 admin 密码；
- [ ] 设置 `ALLOW_DEFAULT_ADMIN=false`、`NODE_ENV=production`、显式 `JWT_SECRET`；
- [ ] MySQL 使用**只读账号**（仅 SELECT 权限）并限制来源 IP；
- [ ] 若做浏览器公网/内网部署，评估 CORS（当前任意 origin + credentials）与反向代理配置（`trust proxy` 需在 `index.js` 显式开启，否则限流按代理 IP 计算）；
- [ ] 定期归档 `logs/` 与 SQLite（含敏感 LLM prompt）；
- [ ] 生产环境禁用调试接口（`/api/query/messages` 在 production 下自动 404）；
- [ ] 评估 Electron 启动时强杀 5002 端口进程的风险（问题清单 H3），必要时手动确认端口空闲。
