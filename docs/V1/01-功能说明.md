# 01 功能说明

> 版本：V1 · 核对日期：2026-08-12 · 依据：当前代码（`backend/`、`frontend/`、`electron/`、`skills/`）

## 1. 产品概述

XTSQLQueryAgent 是一个“自然语言 → SQL → 结果”的企业级数据查询助手：

- 用户用中文/自然语言描述查询诉求，LLM（默认 DeepSeek）按 Skill 规则逐步调用工具收集表结构信息，最终生成 MySQL 5.7 兼容 SQL；
- 生成的 SQL 经过 LLM 自检（`validate_sql_fields`）与后端只读校验（`sqlValidator`）双重把关后，由用户确认执行；
- 结果以表格展示，可导出 Excel/CSV，可一键 EXPLAIN 与 AI 性能分析；
- 常用 SQL 可收藏复用，并作为新会话的建议问题；
- Skill（表索引/字段配置/DDL/业务域）可在界面内查看、编辑、备份，管理员可一键从 MySQL 同步新表。

## 3. 功能清单（含实现位置）

### 3.1 认证与账号

| 功能 | 说明 | 实现 |
|---|---|---|
| 注册 | 用户名 2-32 位（字母/数字/下划线/中文），密码 ≥6 位 | `routes/auth.js` POST `/register` |
| 登录 | bcrypt 校验，签发 JWT，写入 httpOnly Cookie `xtsql_auth` | `routes/auth.js`、`services/auth.js` |
| 当前用户 | 启动时 `/auth/me` 校验 Cookie 有效性 | `routes/auth.js`、`AuthContext.jsx` bootstrap |

| 限流 | 写操作 10 次/h/（IP+用户名），读操作 100 次/h/IP | `middleware/rateLimit.js` |

### 3.3 AI 能力（Agent）

| 功能 | 说明 | 实现 |
|---|---|---|
| Agent 循环 | 每轮：拼装请求 → 调 LLM → 解析 → 执行工具 → 写回，最多 `agent_max_tool_calls` 轮 | `services/llm.js` `runSqlAgent`（CC 路径）、`services/responsesApi.js`（Responses 路径） |
| 工具集（当前 6 个） | `get_domain_index`、`get_sliced_index`、`get_table_schema`、`request_tag_confirmation`、`request_user_choice`、`validate_sql_fields` | `services/toolFuncs.js` `tools` |
| 工具调用去重 | 同一会话内同工具+同参数自动拦截；一次性工具调用后从 LLM 视野剪枝 | `llm.js` `checkAndFilterDuplicateCall` / 剪枝逻辑 |
| 工具并行执行 | 同一轮多个工具 `Promise.all` 并行，写回按原始顺序 | `llm.js` 工具执行三阶段 |
| 已调用工具清单 | 每轮请求尾部追加 system 提示（checklist），防止长上下文注意力衰减 | `llm.js` `buildToolCallChecklistMessage` |
| 长上下文压缩 | 已消费的 `get_sliced_index` 结果折叠（去 related_tables），保留规则/约束 | `llm.js` `compactConsumedToolResults` |
| 用户确认弹窗 | `request_user_choice` 单次 1-3 题、每题 1-4 选项、链式“上一步/下一个” | `toolFuncs.js`、`UserChoiceDialog.jsx` |
| 标签确认弹窗 | 用户纠正表名时建议把术语加入表标签 | `request_tag_confirmation`、`ConfirmDialog.jsx` |
| SQL 质量自检 | 输出前必调 `validate_sql_fields`（R1 字段归属 / R2 反引号 / R3 MySQL5.7 / R5 LIMIT） | `services/validators.js`、`services/sqlParser.js` |
| 流式思考过程 | DeepSeek `reasoning_content` 实时透传并落库，结束剥离误入 content 的 thinking | `llm.js`、`sseStream.js` |

## 4. UI 布局与交互

```
┌─────────────┬──────────────────────────────────────────────┐
│ 侧边栏       │ 页签栏：聊天 / SQL查询1 / SQL查询2 ...  [主题] │
│ ・新对话建议  ├──────────────────────────────────────────────┤
│ ・会话列表    │ 聊天区：消息气泡 / Round 日志组 / 用户确认弹窗  │
│ ・配置(admin) │ SQL 页签：Monaco 编辑器 + EXPLAIN/查询按钮    │
│ ・Skill      │ 结果区：表格 + 导出Excel + 执行计划 + AI分析    │
│ ・用户卡片    ├──────────────────────────────────────────────┤
│             │ 输入区：模型名 / token进度条 / 发送/停止        │
└─────────────┴──────────────────────────────────────────────┘
```

关键交互细节：

- 输入框回车发送、Shift+Enter 换行，发送中按钮变为“停止”（红色转圈）；
- 聊天消息按 round 分组展示（`RoundGroup`），工具日志可折叠，思考过程可展开且不被流式刷新折叠；
- assistant 消息下方提供“打开 SQL 页签 / 复制并执行 / 收藏”操作；
- 深色/浅色主题切换（localStorage `xtsql_theme`，挂载前预应用避免闪烁）；
- 配置与 Skill 均为右侧 Drawer，Skill 抽屉可拖拽宽度与分区高度；
- **流式滚动跟随**：生成中用户上翻查看历史时滚动条保持不动，不被实时输出拉回底部；只有贴近底部（<100px）时才自动跟随最新内容（2026-08-13 修复）。
- **缓存命中率明细**：鼠标悬停 assistant 消息上的"缓存命中率"徽标，tooltip 除累计命中率外还展示**各轮（Round 0..N）命中率**明细；实时生成与历史回看两条路径均有该数据（2026-08-13 新增，无需改后端）。
- **Token 展示语义（2026-08-13 明确）**：输入区模型名右侧的数字（带时钟图标）为**该会话累计消耗 token**（含输出，按 API usage 计，hover 可见说明）；其右侧进度条为**当前上下文长度**（本地估算，相对警告阈值，hover 可见说明、点击查看完整上下文 JSON）；两者口径不同，避免混淆。

## 5. 非功能特性

| 类别 | 特性 |
|---|---|
| 流式体验 | SSE + `socket.setNoDelay` 关 Nagle；前端增量解码防中文截断、半行缓冲防解析失败 |
| 超时体系 | 客户端断连即时中止；单轮 fetch 120s；流中单次 read 30s；整体 SSE 5min；查询 30s；连接获取 15s |
| 数据安全 | 只读 SQL（SELECT/WITH 白名单 + 危险函数黑名单 + 多语句拒绝 + MySQL 条件注释拒绝）；`multipleStatements=false`；Skill 路由路径穿越防护 |
| 可观测性 | 按日期/用户分文件的 LLM 日志（`logs/YYYY-MM-DD/{username}_llm.log`）、Winston 系统日志、Electron 启动日志、skill_logs 变更审计 |
| 离线可用 | Monaco、语法高亮、markdown 渲染均本地依赖，无 CDN |
