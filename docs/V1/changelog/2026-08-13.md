## 一、功能修复

### F1. 空会话加载消息崩溃（前端）

- 现象：进入页面报 `加载消息失败: TypeError: Cannot read properties of undefined (reading 'role')`；且新建空会话后切到有内容的会话、再切回空会话，会残留上一会话的消息。
- 根因：`App.jsx` `loadMessages` 的"按问题分段"第二遍扫描在 `messages` 为空数组时访问 `data.messages[0].role` 越界，`setMessages(loaded)` 永不执行。
- 修复：空会话早退（`setMessages([])` + `setFavoriteStates({})`）+ 三处防御判空（usage 扫描 / 分段扫描 / 第二遍扫描）。
- 提交：`5c93eca`；产物：`frontend/dist` 重建。

### F2. 流式输出强制滚动到底部（前端）

- 现象：Agent 生成中用户上翻查看历史，滚动条被实时输出反复拉回底部。
- 根因：chunk 与 LLM/工具日志事件各有一处**无条件** `scrollIntoView({ behavior: 'smooth' })`，未判断用户是否上翻。
- 修复：新增 `isNearBottomRef`（距底部 < 100px 视为贴底），两处流式滚动加守卫；消息数量增长的自动滚动 effect 区分"切换会话"（恢复上次位置）与"同会话流式增长"（仅贴底跟随）。
- 提交：`fdbe944`；产物：`frontend/dist` 重建。

### F3. 域路由状态改为"问题级"，新话题可重新路由（后端）

- 现象：同一会话先问「查询当月新增的排课数量」（已切片 course），再问全新话题「当月新增线索数量」，模型调用 `get_sliced_index(["crm"])` 被会话级剪枝拦截，无法路由 CRM 域（会话 594 实证）。
- 修复（`llm.js` + `responsesApi.js`，CC/Responses 双路径对齐）：
  1. 新增 `detectUserChoiceContinuation(messages)`：最后一条 user 消息紧邻的前一条是含 `<!--user_choice:` 标记的 tool 消息 → 判定为 `request_user_choice` 中断后的续问；
  2. 新增 `resetRegistryForNewQuestion(reg, messages)`：`validateSqlFields*` 始终重置；域路由状态（getDomainIndexCalled / slicedDomains / tableSchema / termConfirmed / userChoiceAsked / getTablesCalled）**新问题清空、续问保留**；

### P2. sanitizeMessagesForLLM 告警（by design）

- 现象：`warn: Sanitizing incomplete assistant tool_calls`，本次对应会话 591（8/12 09:48 提问被中断）。
- 说明：`saveMessagesToDb` 在工具结果写回前保存，中断窗口会留下悬挂 tool_call；加载时补合成响应并告警，属预期防御。
- 可选优化：中断时主动补齐合成响应 + 将告警降级，降低噪音；历史 13 行脏数据可清理。

### P4. 缓存命中率计算核查（结论：正确，附 3 个维护项）

- 定义：命中率 = `cached_tokens / prompt_tokens`（DeepSeek 约定 `prompt_tokens = hit + miss`），已用日志实证（如 session 591：prompt=3242, hit=3200, miss=42，DB 存储值与日志完全一致）。
- 链路：后端日志 hit_rate（llm.js `hit/(hit+miss)`）→ DB usage 行（prompt/cached 原样入库）→ 前端流式（done 累积 0..lastRound）与历史回看（v5.19 按 user 分段、段内累积 0..round）公式一致。
- 全库扫描：335 个含 usage 的会话，比率均落在 0-100%；仅 2 个会话（525、576）段内无 usage（prompt=0），前端显示层已优雅跳过。
