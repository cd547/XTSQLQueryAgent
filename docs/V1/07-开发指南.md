## 3. 扩展点

### 3.1 新增一个工具

1. 在 `toolFuncs.js` 的 `tools` 数组加 `new DynamicTool({ name, description, params, func })`：
   - 描述控制在 300 字内（token 敏感）；
   - `func` 返回值约定：给 LLM 看的必须是 `content` 字符串；结构化数据（`valid/errors/ids` 等）单独字段返回（参考 `validate_sql_fields` / `request_user_choice`）；
   - 若工具需要状态登记 → 第 2 步；需要剪枝 → 第 3 步。
2. 需要会话级状态：在 `llm.js` `getOrCreateRegistry` 的 reg 对象加字段；在工具执行阶段 2（`Promise.all` 回调内）写值；若需 LLM 可见，在 `buildToolCallChecklistMessage` 加展示。
3. 需要剪枝：在 `llm.js` 剪枝 filter（约 L1285）加规则；**必须同时保留“幻觉调用拦截”**（阶段 1 检查 `availableToolNames`），否则 LLM 可能调用已剪枝工具拿到错误提示。
4. 判断状态作用域（2026-08-13 起）：域路由类状态（get_domain_index / sliced / schema / tag / choice 计数）一律为**问题级**，新问题由 `resetRegistryForNewQuestion` 清空（`request_user_choice` 中断后的续问保留，检测见 `detectUserChoiceContinuation`）；`validateSqlFields*` 始终重置。新工具要加状态时，按此规则接入重置逻辑（见 03-核心流程 2.4）。
5. 测试：新建 `backend/test-<name>.mjs`，参考 `test-request-user-choice.mjs` / `test-validate-sql-fields.mjs` 的注入式写法（`llmCaller`/`getDbFn` 可注入，不依赖真实网络/DB）。

### 3.2 新增 SSE 事件类型

1. 后端在 `llm.js`（或 responsesApi.js）`yield { type: 'xxx', ... }`；
2. `query.js` 的 `for await` 分发循环加分支：透传前端 + 按需落库；
3. 若需落库新字段：`db/sqlite.js` 加迁移（`PRAGMA table_info` + `ALTER TABLE ADD COLUMN`），`messages` 的 INSERT 语句同步；
4. 前端 `App.jsx` 的 SSE 回调加 `else if (data.type === 'xxx')` 处理。

### 3.3 更换/新增 LLM Provider

1. `llm.js` `getProviderConfig` 静态表加 provider（baseURL + 默认 model）；
2. `session.js` 的 summarize 与 `query.js` explain-analyze 的 provider 分支同步；
3. `query.js` `validateLlmProvider` 白名单放开（explain-analyze）；
4. `frontend/src/components/ConfigPanel.jsx` 目前硬编码 `provider: 'deepseek'`，如需切换需改为 Select 并去掉 `saveLlm` 里的强制覆盖；
5. 注意 `thinking:{type:'enabled'}` 是 DeepSeek 特有字段，OpenAI 等需移除；Responses 路径的 `reasoning:{effort}` 同理。

### 3.4 新增数据库表/字段

- SQLite 应用库：改 `db/sqlite.js`（建表 + 迁移 + 索引），保持非破坏式；
- MySQL 目标库：不改代码结构，改 `skills/sql-creator-skill-v2/`（table_index + domains + ddl + field_config），或走界面“添加表”流程。

## 4. 关键设计约束（改了会坏）

1. **messages 是单一真实源**：SSE 事件、DB、`lastMessages` 都从同一 `messages` 数组派生；checklist 消息只进 requestMessages，**禁止 push 进 messages**；
2. **工具写回必须按原始顺序**：`execResults` 是 Promise.all 结果（无序），写回遍历必须用 `validToolCalls` 顺序；
3. **DeepSeek thinking 协议**：两个 user 之间发生过工具调用时，assistant 的 `reasoning_content` 必须回传；无工具调用时可剥离；
4. **中断场景的 tool_calls 合法化**：保存时机早于 tool 响应入栈，读取时 `sanitizeMessagesForLLM` 补合成响应，不要改成“删掉 tool_calls”；
5. **SSE 解析必须增量 UTF-8**：`decoder.decode(value, {stream:true})` + 半行缓冲，否则中文跨 chunk 变乱码（前端 `sseStream.js` 与后端 llm.js 都是这个模式）；
6. **TDZ 陷阱**：`try/catch` 是不同作用域，`catch` 要访问的变量必须在 try 外声明（`/explain-analyze`、responsesApi catch 都踩过）；
7. **Express 4 不接 async 异常**：新路由用 `asyncHandler` 包装，或自己 try/catch；全局兜底只记录日志不退出进程；
8. **pool 单例锁**：`getPool` 有 `poolInitPromise` 防并发重建，改配置指纹/重建逻辑时保持该模式；
9. **前端请求版本号**：切会话会 abort 旧流并自增 `streamRequestIdRef`，SSE 回调顶部比对，失效则丢弃写入——新增异步写入路径时遵循同样模式。

## 7. 常见开发陷阱速查

| 陷阱 | 说明 |
|---|---|
| Node 版本 | 后端必须 Node 24；npm install 也要用 Node 24 的 npm |
| 编码 | 全部源码/文档 UTF-8 无 BOM；PowerShell `Get-Content` 默认按 ANSI 读会显示乱码，加 `-Encoding UTF8` |
| 端口 | 5002 被占用时 Electron 会强杀占用者；开发时先确认 |
| 空响应 | `/generate` 必须传 `schemaMode:"stream"`，否则悬挂 |
| apiKey 回填 | `/config/llm` 传空 apiKey 会保留旧值（F3），这是特性不是 bug |
| 无效配置 | `agent_timeout_ms` 当前未消费，改 LLM 超时要动 `LLM_TIMEOUTS.FETCH_MS`（见问题清单 A18） |
| 会话归属 | 所有会话/消息接口都要过 `sessionBelongsToUser`，新接口别漏 |
| 剪枝与拦截 | 只剪枝不拦截 = LLM 幻觉调用会执行；只拦截不剪枝 = 浪费 token |
| 空消息数组 | `loadMessages` 等“按分段扫描”逻辑必须先判空，曾因空会话访问 `data.messages[0].role` 越界崩溃（见问题清单 E1） |
| 流式自动滚动 | 必须判断“用户是否贴近底部”再跟随（`isNearBottomRef`，100px 阈值），否则生成中上翻会被拉回底部（见问题清单 E2） |
| 数据库 | SQLite 是 WAL 模式，备份要带 -wal/-shm；MySQL 是只读使用 |

## 8. 风格与约定

- ESM（`"type":"module"`），导入路径带 `.js` 后缀；
- 日志用 `logger`（winston）而非 console（业务代码）；`console.warn` 仅用于必须立即可见的诊断（工具参数修复提示等）；
- 用户相关日志按用户分文件时，用户名必须过 `sanitizeUsername`；
- 文件路径必须经 `isPathSafe` 校验（skill 路由）；
- 破坏性变更（DB 迁移、协议变更）遵循“兼容旧数据/旧调用方”原则，参考 `api_mode` 迁移模式；
- 中文注释与提交信息（项目现状），新代码保持一致。

## 9. Token 成本维护（2026-08-13 现状）

- SKILL.md 与 6 个工具描述已做过一轮精简（详见 changelog 2026-08-13 O1/O2）：当前 SKILL.md 约 2269 真实 token/轮、工具描述合计约 315 真实 token/轮，是每轮请求的**固定成本**。
- 维护要求：新增工具或规则时保持描述精简（参数约束交给 schema，避免描述与 schema 重复）；SKILL.md 是最大头，改动后注意与 `validate_sql_fields` 工具描述的行为句（必调/重写再校验）不要重复；若删掉 SKILL.md 规则 9 的对应约束，须把行为句补回工具描述。
- 注意：系统提示/tools 定义变化会让改后**首次请求 prefix cache 失效一次**，之后恢复命中。
