## 3. 扩展点

### 3.1 新增一个工具

1. 在 `toolFuncs.js` 的 `tools` 数组加 `new DynamicTool({ name, description, params, func })`：
   - 描述控制在 300 字内（token 敏感）；
   - `func` 返回值约定：给 LLM 看的必须是 `content` 字符串；结构化数据（`valid/errors/ids` 等）单独字段返回（参考 `validate_sql_fields` / `request_user_choice`）；
   - 若工具需要状态登记 → 第 2 步；需要剪枝 → 第 3 步。
2. 需要会话级状态：在 `llm.js` `getOrCreateRegistry` 的 reg 对象加字段；在工具执行阶段 2（`Promise.all` 回调内）写值；若需 LLM 可见，在 `buildToolCallChecklistMessage` 加展示。
3. 需要剪枝：在 `llm.js` 剪枝 filter（约 L1285）加规则；**必须同时保留“幻觉调用拦截”**（阶段 1 检查 `availableToolNames`），否则 LLM 可能调用已剪枝工具拿到错误提示。
4. 判断状态作用域（2026-08-13 起）：域路由类状态（sliced / schema / tag / choice 计数）一律为**问题级**，新问题由 `resetRegistryForNewQuestion` 清空（`request_user_choice` 中断后的续问保留，检测见 `detectUserChoiceContinuation`）；`validateSqlFields*` 始终重置。新工具要加状态时，按此规则接入重置逻辑（见 03-核心流程 2.4）。`get_domain_index` 已废弃（2026-08，域清单改为内嵌到 system 消息，见 03-核心流程 2.5），工具定义保留为兼容旧会话，**不要**再为它加状态字段或剪枝分支。
5. 测试：新建 `backend/test-<name>.mjs`，参考 `test-request-user-choice.mjs` / `test-validate-sql-fields.mjs` 的注入式写法（`llmCaller`/`getDbFn` 可注入，不依赖真实网络/DB）。

### 3.2 新增 SSE 事件类型

1. 后端在 `llm.js`（或 responsesApi.js）`yield { type: 'xxx', ... }`；
2. `query.js` 的 `for await` 分发循环加分支：透传前端 + 按需落库；
3. 若需落库新字段：`db/sqlite.js` 加迁移（`PRAGMA table_info` + `ALTER TABLE ADD COLUMN`），`messages` 的 INSERT 语句同步；
4. 前端 `App.jsx` 的 SSE 回调加 `else if (data.type === 'xxx')` 处理。

### 3.3 更换/新增 LLM Provider

1. `llm.js` `getProviderConfig` 静态表加 provider（baseURL + 默认 model）；
2. `session.js` 的 summarize 与 `query.js` explain-analyze 的 provider 分支同步；
3. `query.js` `validateLlmProvider` 白名单放开（explain-analyze）；
4. `frontend/src/components/ConfigPanel.jsx` 目前硬编码 `provider: 'deepseek'`，如需切换需改为 Select 并去掉 `saveLlm` 里的强制覆盖；
5. **思考模式 thinking 字段**（2026-08-24 更新，v5.20）：
   - DeepSeek Chat Completions API: `thinking: { type: 'enabled' }`（或 `'disabled'`） + **顶层** `reasoning_effort: 'low'|'medium'|'high'`，二者必须平级（不能用对象嵌套，详见第 4 节第 10 条）；
   - Responses API: `reasoning: { effort: 'low'|'medium'|'high' }` 顶层一个对象（与 CC 协议不同）；
   - OpenAI / 其他 provider: 直接去掉 `thinking` / `reasoning` 字段；
   - 改完后务必实测 `delta.reasoning_content` / `reasoning_content` 真的非空。

### 3.4 新增数据库表/字段

- SQLite 应用库：改 `db/sqlite.js`（建表 + 迁移 + 索引），保持非破坏式；
- MySQL 目标库：不改代码结构，改 `skills/sql-creator-skill-v2/`（table_index + domains + ddl + field_config），或走界面“添加表”流程。

## 4. 关键设计约束（改了会坏）

1. **messages 是单一真实源**：SSE 事件、DB、`lastMessages` 都从同一 `messages` 数组派生；checklist 消息只进 requestMessages，**禁止 push 进 messages**；
2. **工具写回必须按原始顺序**：`execResults` 是 Promise.all 结果（无序），写回遍历必须用 `validToolCalls` 顺序；
3. **DeepSeek thinking 协议**：两个 user 之间发生过工具调用时，assistant 的 `reasoning_content` 必须回传；无工具调用时可剥离；
4. **中断场景的 tool_calls 合法化**：保存时机早于 tool 响应入栈，读取时 `sanitizeMessagesForLLM` 补合成响应，不要改成"删掉 tool_calls"；
5. **SSE 解析必须增量 UTF-8**：`decoder.decode(value, {stream:true})` + 半行缓冲，否则中文跨 chunk 变乱码（前端 `sseStream.js` 与后端 llm.js 都是这个模式）；
6. **TDZ 陷阱**：`try/catch` 是不同作用域，`catch` 要访问的变量必须在 try 外声明（`/explain-analyze`、responsesApi catch 都踩过）；同理 `useEffect(..., [someState])` 依赖数组在 `useEffect` 调用时**立即求值**，`someState` 必须在该行之前已用 `const` 声明，否则触发 TDZ（前端 useChatStream 抽离时踩过，见 06 问题清单 E11 经验）；
7. **Express 4 不接 async 异常**：新路由用 `asyncHandler` 包装，或自己 try/catch；全局兜底只记录日志不退出进程；
8. **pool 单例锁**：`getPool` 有 `poolInitPromise` 防并发重建，改配置指纹/重建逻辑时保持该模式；
9. **前端请求版本号**：切会话会 abort 旧流并自增 `streamRequestIdRef`，SSE 回调顶部比对，失效则丢弃写入——新增异步写入路径时遵循同样模式。
10. **DeepSeek Chat Completions API 的 `reasoning_effort` 必须在请求体顶层**（与 `thinking` 平级），嵌套在 `thinking` 内会被静默忽略。**示例（正确）**：
    ```js
    requestParams = {
      ...requestParams,
      ...buildThinking(reasoningConfig)  // 返回 { thinking: {...}, reasoning_effort: '...' }
    }
    // 错误：requestParams.thinking = buildThinking(...) 会把 reasoning_effort 嵌套
    ```
    参考 [create-chat-completion](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion) 官方文档。**改 `buildThinking` 时务必实测** `delta.reasoning_content` 真的非空，不能凭代码注释或经验判断（见 06 问题清单 E4 教训）。
11. **Responses API 路径与 Chat Completions 路径的 ctx 字段必须对齐**：抽离或修改时检查 `runSqlAgentResponsesHandler`（[responsesApi.js:712](file:///d:/Ai_Program_Files/XTSQLQueryAgent/backend/src/services/responsesApi.js#L712)）的 destructure 与 `query.js` 调用的 ctx 字段是否一致。新增字段时**两处都要加**，否则 generator 内引用会 ReferenceError（见 E5 教训）。
12. **思考模式 `reasoning_effort` 行为差异**：
    - `low`：轻量推理，reasoning_content 较短；
    - `medium`：适度推理，content 中等；
    - `high`：深度推理，content 最长。
    三档都需要后端正确传 `reasoning_effort`（见第 10 条），否则全部档位都看不到思考过程。
13. **抽离 App.jsx 到 hook 时 useEffect 依赖数组 TDZ**（2026-08-24 新增，E11）：当 hook 内部 `useEffect(() => {...}, [someState])` 的 `someState` 是 hook 外部传入的 state 时，要确认该 state 的 `useState` 声明位置在 hook 调用**之前**。否则首次 render 即报 `Cannot access 'someState' before initialization`。**典型场景**：抽离 `useXxx` 时，把 state 声明和 hook 调用顺序调换会导致 TDZ。**解法**：要么调换声明顺序，要么把 useEffect 移到 state 声明之后。
14. **工具 func 入参必须用 `parseToolArgs(input, toolName)`**（2026-08-24 新增）：5 个有入参的工具（`get_table_schema` / `request_tag_confirmation` / `request_user_choice` / `get_sliced_index` / `validate_sql_fields`）func 入口统一调用 `parseToolArgs`，**禁止**自己写 string/object 双兼容 + try/catch 模板。返回 `{parsed}` 成功 / `{error, content}` 失败（`content` 必带 `⚠️ <toolName>:` 前缀）。新增工具必须用同一函数，避免再写 5 遍 ~10 行重复代码。
15. **工具 func 错误返回必须用 `{error, content}` 结构**（2026-08-24 新增，O4）：错误时返回 `{error: "msg", content: "⚠️ ..."}`，**禁止**直接返回 string。caller（`llm.js` L1854）`toolMessageContent = rawResult` 直接读 object.content 字段，string 错误返回也能 work，但失去 `error` 字段（caller 未来要根据严重度分流时缺信息）。返回结构化便于 debug 与扩展。
16. **跨文件字符串硬编码必须抽常量**（2026-08-24 新增，O8）：当一个文件输出某个特定字符串（如 DDL 缺失标记），另一个文件 `includes()` / `===` 模式匹配它时，必须抽 `export const` 常量两边都 import。例：`MISSING_DDL_BLOCK(name)` 在 `toolFuncs.js` 定义并 `export`，`validators.js:308` `import` 引用。**反面教训**：早期 L482 写 `\`-- 表 ${t} 的DDL不存在\``，L308 也写一遍，O8 第一次只改 L482 忘改 L308 → 修空格都会漏改一处。
17. **多会话并行流式架构**（2026-08-24 新增，O16 / E23）：前端必须支持"用户在某会话发起 LLM 流时切到其他会话不中断"，但**全局同一时间只允许 1 个 LLM 流**（避免双跑抢资源）。四个核心 ref / state：
    - `messagesBySession: { [sessionId]: Message[] }`：每个会话独立消息列表；
    - `streamBatchesRef: { [sessionId]: { controller, version, isLoading } }`：每个流独立 controller + 版本号；
    - `isGlobalStreamingRef: boolean`：全局流守卫，handleSend 入口 `if (isGlobalStreamingRef.current) { warning; return; }`；
    - `streamingSessionId: string | null`：当前具体在流的 sessionId（**区别于 loading 全局流标志**）。
    handleSend 入口 `isGlobalStreamingRef.current=true` + `setStreamingSessionId(targetSessionId)`；finally `isGlobalStreamingRef.current=false` + `setStreamingSessionId(prev => prev === currentFlowSessionId ? null : prev)`。**禁止**把 `messages` 改回单数组，**禁止**把 abort 写回 `handleSessionClick`（会误杀后台流）。
18. **`messagesBySession` 状态结构与 UI 派生**（2026-08-24 新增）：派生 `messages = currentSessionId ? messagesBySession[currentSessionId] || [] : []`，UI 始终只读 `currentSessionId` 对应的列表。SSE 回调按 `currentFlowSessionId`（流式过程中的 sessionId，可能与 UI 视图不同）写入 `messagesBySession[currentFlowSessionId]`，**两套 id 必须解耦**。useEffect `[currentSessionId]` 触发 `loadMessages` 必须加守卫 `if (streamBatchesRef.current[currentSessionId]) return;`，否则会覆盖正在流式累积的消息。
19. **`user_choice` 弹窗 sessionId 透传**（2026-08-24 新增，E9）：弹窗可能跨会话触发（A 在流时切到 B 弹起），提交时必须把**发起方 sessionId** 透传给 handleSend，否则内容会写到当前 UI 视图的会话。`useUserChoice` 弹窗 state 加 `sessionId: payload.sessionId || null`；`openUserChoiceRequest` 接 `payload.sessionId`；`handleSubmitUserChoice` / `handleCancelUserChoice` 把 `prev.sessionId` 透传给 `submitRef.current(text, openerSessionId)`。handleSend 接收 `overrideSessionId` 入参，优先级 `overrideSessionId > currentSessionId`。**禁止**让 `handleSubmitUserChoice` 直接调 `handleSend(text)` 走默认 currentSessionId。
20. **finally 块 ref 清理的"自己是最新流"守卫**（2026-08-24 新增，E17 / E18）：handleSend finally 块清理 `streamBatchesRef` / `roundUsagesRef` / `abortControllerRef` 时，**必须**用 `batch.version === myStreamVersion` 守卫：
    - `const batch = streamBatchesRef.current[currentFlowSessionId];`
    - `if (batch && batch.version === myStreamVersion) delete streamBatchesRef.current[currentFlowSessionId];`
    - `delete roundUsagesRef.current[currentFlowSessionId];`
    防止后台流（新版本）的 entry 被旧流的 finally 误清。**禁止**无脑 `delete streamBatchesRef[flowSessionId]`（flowSessionId 是闭包内初始 id，可能已被 meta 事件迁移到 newId）。

## 7. 常见开发陷阱速查

| 陷阱 | 说明 |
|---|---|
| Node 版本 | 后端必须 Node 24；npm install 也要用 Node 24 的 npm |
| 编码 | 全部源码/文档 UTF-8 无 BOM；PowerShell `Get-Content` 默认按 ANSI 读会显示乱码，加 `-Encoding UTF8` |
| 端口 | 5002 被占用时 Electron 会强杀占用者；开发时先确认 |
| 空响应 | `/generate` 必须传 `schemaMode:"stream"`，否则悬挂 |
| apiKey 回填 | `/config/llm` 传空 apiKey 会保留旧值（F3），这是特性不是 bug |
| 无效配置 | `agent_timeout_ms` 当前未消费，改 LLM 超时要动 `LLM_TIMEOUTS.FETCH_MS`（见问题清单 A18） |
| 会话归属 | 所有会话/消息接口都要过 `sessionBelongsToUser`，新接口别漏 |
| 剪枝与拦截 | 只剪枝不拦截 = LLM 幻觉调用会执行；只拦截不剪枝 = 浪费 token |
| 空消息数组 | `loadMessages` 等“按分段扫描”逻辑必须先判空，曾因空会话访问 `data.messages[0].role` 越界崩溃（见问题清单 E1） |
| 流式自动滚动 | 必须判断"用户是否贴近底部"再跟随（`isNearBottomRef`，100px 阈值），否则生成中上翻会被拉回底部（见问题清单 E2） |
| 数据库 | SQLite 是 WAL 模式，备份要带 -wal/-shm；MySQL 是只读使用 |
| reasoning_effort 字段位置 | 必须放在请求体顶层与 `thinking` 平级，**禁止嵌套**在 `thinking` 对象内（DeepSeek 会静默忽略，导致 reasoning_content 永远空，详见第 4 节第 10 条 / E4） |
| App.jsx 抽 hook 的 useEffect 依赖 | 依赖数组在 useEffect 调用时立即求值，传入的 state 必须在该 useEffect 之前已用 `const` 声明，否则触发 TDZ `Cannot access 'X' before initialization`（见第 4 节第 13 条 / E11） |
| Responses API ctx 字段对齐 | 抽离/新增字段时，`runSqlAgentResponsesHandler` 的 destructure 与 `query.js` 调用 ctx 必须**两处同步**，否则 generator 内 ReferenceError（见 E5） |
| 工具 func 入参解析 | 必须用 `parseToolArgs(input, toolName)`，**禁止**自己写 string/object 双兼容 + try/catch 模板（见第 4 节第 14 条 / O1） |
| 工具 func 错误返回 | 必须 `{error, content}`，**禁止**返回 string（见第 4 节第 15 条 / O4） |
| 跨文件字符串硬编码 | 一个文件输出特定字符串被另一文件 `includes()`/`===` 匹配时，必须抽 `export const` 常量两边 import（见第 4 节第 16 条 / O8 教训：早期 L482/L308 两处硬编码 O8 第一次只改一处漏改另一处） |
| 多会话流式入口守卫 | handleSend 入口必须 `if (isGlobalStreamingRef.current) { warning; return; }`；**禁止**在已经有流时并发发起第二个（见第 4 节第 17 条 / E23） |
| streamingSessionId vs loading | `loading` 是全局流标志（任意 LLM 流在跑），`streamingSessionId` 是具体在流的 sessionId；UI 按钮态用后者（`isCurrentSessionStreaming = currentSessionId === streamingSessionId`）判断，避免"在 B 看 A 在流时 B 顶部显示停止按钮"UX bug（见第 4 节第 17 条 / E24） |
| user_choice 弹窗透传 | 弹窗 state 必须存 `sessionId`（发起方）；提交/取消时把 `prev.sessionId` 透传给 handleSend 的 `overrideSessionId` 入参；**禁止**直接调 `handleSend(text)` 走默认 currentSessionId（见第 4 节第 19 条 / E9） |
| `batch.version` 守卫 | finally 块清理 `streamBatchesRef[xxx]` 必须先检查 `batch.version === myStreamVersion`，避免后台流（新版本）的 entry 被旧流 finally 误清（见第 4 节第 20 条 / E17 / E18） |

## 8. 风格与约定

- ESM（`"type":"module"`），导入路径带 `.js` 后缀；
- 日志用 `logger`（winston）而非 console（业务代码）；`console.warn` 仅用于必须立即可见的诊断（工具参数修复提示等）；
- 用户相关日志按用户分文件时，用户名必须过 `sanitizeUsername`；
- 文件路径必须经 `isPathSafe` 校验（skill 路由）；
- 破坏性变更（DB 迁移、协议变更）遵循“兼容旧数据/旧调用方”原则，参考 `api_mode` 迁移模式；
- 中文注释与提交信息（项目现状），新代码保持一致。
